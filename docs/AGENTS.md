# Rules for agents (and humans) working in lean_dft

This repository is developed largely by AI agents under human direction. These rules are binding for every contribution.
The architecture is described in [`ARCHITECTURE.md`](ARCHITECTURE.md).

## 1. Before writing anything

1. **Search first; never duplicate.** Look in Mathlib, then Physlib (`.lake/packages/Physlib`: `Physlib/`, `QuantumInfo/`), then this
   repository. If it exists, use it. If it almost exists, extend it in the right place.
2. **Check that nobody else is working there.** Run `git status` and look at `docs/LOCKS.md`. Do not edit files another agent is changing.
   Add a line to `docs/LOCKS.md` while you work on a folder, and remove it when you are done.

## 2. Where things go (layering is enforced by `scripts/check_layers.py`)

| Library | Content | May import |
|---|---|---|
| `ForMathlib` | pure mathematics, no physics; mirrors Mathlib paths and namespaces | Mathlib |
| `QM` | generic quantum mechanics and many-body theory (not specific to DFT) | Mathlib, Physlib, ForMathlib |
| `DFT` | density-functional theory proper | all of the above |

- `PhyslibAlpha` (unreviewed) must not be imported.
- Folders inside a library must not import each other in a cycle. If you need something from a "later" folder, the
  thing you need is in the wrong place: move it down.
- Namespaces of *new* code follow folders (`DFT.Lattice.HK`, `QM.ManyBody`, ...); new `ForMathlib` code uses the Mathlib
  namespace of the object. Files moved into `ForMathlib`/`QM` from `DFT` keep their `DFT.…` names until upstreamed
  (no cosmetic renames, §5).
- The folder order inside each library is in `ARCHITECTURE.md`.
- Import only what you use (`lake exe shake` must not report your file).

## 3. Rigor (enforced in CI)

Status of the gates (update when a report-only gate becomes enforcing):

| Check | Script | Mode |
|---|---|---|
| Axiom audit + its self-test | `scripts/check_axioms.sh`, `scripts/test_axiom_check.sh` | **enforcing** |
| Forbidden constructs, duplicate declaration names | `scripts/check_hygiene.py` | **enforcing** |
| Unjustified `maxHeartbeats` (49 at the start), module docstrings | `scripts/check_hygiene.py --strict` | report-only (backlog) |
| Layering (library order, folder DAG) | `scripts/check_layers.py` | **enforcing** |
| Blueprint references exist | `lake exe checkdecls blueprint/lean_decls` | **enforcing** |

- No `sorry`, no `axiom`, no `native_decide`, no `implemented_by`/`unsafe`. `scripts/check_axioms.sh` allows only `propext`,
  `Classical.choice`, `Quot.sound`. Its self-test `scripts/test_axiom_check.sh` must pass.
- `set_option maxHeartbeats` only with a comment `-- heartbeats: <reason>` on the same or the previous line.
- Files generated by a script carry a header naming the generator, the exact command, and a hash of its inputs;
  CI regenerates them and compares.
- Every file starts with the copyright header and a module docstring (`/-! # Title ... ## Main results -/`).

## 4. Statements need a human

- **Definitions and theorem statements are approved by Miguel before they are proved or changed.** Propose them in the
  blueprint marked `(statement pending approval)`. The kernel checks proofs; only a human can check that a statement means
  what it claims.
- Main results are listed in `docs/MAIN_RESULTS.md` (or tagged in the blueprint). Every main result must appear in the
  blueprint (`checkdecls` + reverse check). Changing the statement of a main result requires explicit sign-off.

## 5. Naming and renaming

- Mathlib naming conventions.
- **Rename only when it clearly makes a lot of sense** (a genuinely opaque name, a wrong namespace). No cosmetic renames.
  A renamed declaration keeps a `@[deprecated (since := "YYYY-MM-DD")] alias` to the old name.

## 6. Versions

Mathlib comes from Physlib. To bump: change the Physlib tag in `lakefile.toml` (and `lean-toolchain` to Physlib's), run
`lake update Physlib`, then rebuild and run all checks. Never bump Mathlib on its own (the old Mathlib auto-update workflow
was removed for this reason).

## 7. Commits

- One concern per commit: never mix restructuring with new mathematics.
- The build, `checkdecls`, the axiom audit and the layering check must pass on every commit.
- Commit messages: `<Area>: <what>` (e.g. `Line/Neumann: Hohenberg–Kohn for H⁻¹ potentials`).
